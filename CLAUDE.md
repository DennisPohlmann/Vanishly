# Vanishly - notes for Claude

Node.js (Express 5, ES modules, plain JavaScript checked by `tsc` via
`jsconfig.json`) one-time secret app. Secrets are encrypted in the browser
(`public/js/vanishly-crypto.js`, shared with the server for `POST /api/v1/share`);
the server keeps only ciphertext in Redis (`src/store.js`) and never sees the
key, which lives in the URL fragment. HTTP app and API in `src/app.js`, optional sign-in (OIDC/Entra ID,
recipients) in `src/auth.js`,
settings in `src/config.js` (`.env.example`), passphrase rules in
`public/js/rules.js` (shared like the crypto module), design templates and page
rendering in `src/theme.js` (`templates/`, `views/`, `translations/`). API
contract: `openapi/openapi.json`, API reference (Scalar) at `/api/docs`.

Check: `npm ci`, `npm run lint`, `npm test` (Redis via `REDIS_URL` or a
local `redis-server`). Run: `docker compose up -d` (published image), `make up` (build) or `npm start`.

Helm chart in `charts/vanishly` (published with every release to
`oci://ghcr.io/dennispohlmann/charts/vanishly`, checked by
`.github/workflows/chart.yml`). A new setting in `src/config.js` also gets
a key in its `values.yaml` `config` block and `values.schema.json`.

Version in `VERSION` and `package.json`; history in `CHANGELOG.md`.
Third-party licenses: `THIRD-PARTY-LICENSES.md`.

Releases: Conventional Commits + semantic-release (`.releaserc.json`). CI
(`.github/workflows/build.yml`) checks every push and PR, publishes
`ghcr.io/dennispohlmann/vanishly:edge` from `main`; `feat`/`fix`/breaking
commits make semantic-release bump the version files, write
`CHANGELOG.md`, commit `chore(release): vX.Y.Z [skip ci]`, tag `vX.Y.Z` and
publish the GitHub release with the tar.gz (+ `.sha256`) and the image tags
`<version>`, `<major>.<minor>`, `latest`. The nightly `image-scan.yml`
scans the published images with Trivy; `codeql.yml` runs CodeQL. The
security checks are listed in `docs/DEVELOPMENT.md`.

Project layout, documentation structure, CI and skills follow
[gameWE-web](https://github.com/DennisPohlmann/gameWE-web).

## Documentation layout

- Root: `README.md` (overview, features, quick start, documentation table,
  building, license), `CHANGELOG.md` (generated), `LICENSE`,
  `THIRD-PARTY-LICENSES.md`, `CLAUDE.md`.
- `docs/`: `INSTALLATION.md` (install, update, uninstall, troubleshooting),
  `CONFIG.md` (all settings), `USAGE.md` (pages, operation),
  `INTERFACE.md` (API, crypto format, Redis keys), `DEVELOPMENT.md` (build,
  tests, CI, releases); repo-specific extras: `screenshots/`.
  Templates: `templates/README.md`. Helm chart: `charts/vanishly/README.md`
  (generated by helm-docs from `README.md.gotmpl` and `values.yaml`).
- New documentation goes into the matching file; no other top-level doc
  files.

## Security is part of every change (mandatory)

1. **Every change:** before you call a change done, commit it or open a PR,
   run the `security-check` skill on the diff and fix what it finds. Say
   which checklist points the change touched and the result.
2. **Every release (standing rule from Dennis):** releases are made by
   semantic-release in CI when `feat`, `fix` or breaking-change commits reach
   `main`. Before pushing such commits to `main`, run the
   `release-security-gate` skill over the whole repo, without asking first.
   Never tag by hand or edit version files / `CHANGELOG.md`; report the gate
   result and ask Dennis for the go before the push.
3. **Sensitive data, every task (standing rule from Dennis):** before you
   call a task done, commit or publish anything, run the
   `security-privacy-audit` skill over the working tree, the diff, docs and
   the commit message, and end the answer with its audit summary. A
   `BLOCKED` finding stops the commit; report only category and location.
4. A finding you cannot fix in scope goes into the answer with file:line,
   impact and a proposed fix. Never silence a check or weaken a validation
   to get green.

## Before every commit (mandatory, standing rule from Dennis)

Run the `pre-commit-checklist` skill before every `git commit`, together
with `security-check` and `security-privacy-audit`, also for small fixes:
docs and OpenAPI in the same commit, Conventional Commit message,
dependency/toolchain updates suggested (not applied), third-party licenses
current, audit summary at the end.

## Invariants that must not break

- The server never gets the key or the plaintext from the browser. Nothing
  sends, logs or stores `location.hash`; the one exception is the sign-in
  round trip, which keeps it in the tab's `sessionStorage` and removes it on
  return (`public/js/app.js`, docs/SECURITY.md). Only `POST /api/v1/share`
  encrypts on the server, and it keeps neither plaintext nor key.
- A view is taken only by the Lua script in `src/store.js` (atomic); a GET
  of `/s/:id` uses no view (link previews must not burn secrets).
- Passphrase verifiers are compared as SHA-256 with `timingSafeEqual`;
  wrong attempts are counted and burn the secret at the limit.
- Ids are checked with `validId()` before they reach Redis.
- Sign-in (`src/auth.js`) is optional and off by default. A secret with
  recipients is handed out (and its metadata shown) only after the
  recipient check in `src/app.js` (`mayOpen`), which runs before the
  passphrase check and the view count. Recipients are stored only as HMACs.
- No inline scripts or styles in views (CSP `script-src 'self'`); page data
  for scripts only as `<script type="application/json">` with `<` escaped.
- Template output is escaped (`{{ }}`); `{{{ }}}` only for HTML built in
  `src/theme.js`/`src/app.js`. Template files: plain files, no symlinks.
- Logs never contain ids (`:id`), IPs, user agents, keys or secrets.
- `.env`, `.env.local` stay ignored; examples use `change-me` or
  `example.com`.
- The crypto format is versioned (`v: 1`); a change needs a new version and
  keeps decrypting v1 until those secrets have expired.
