## [3.0.0](https://github.com/DennisPohlmann/Vanishly/compare/v2.0.0...v3.0.0) (2026-11-20)

### ⚠ BREAKING CHANGES

* **tokens:** "status" no longer includes burn. Tokens and admin
  policies made before keep both. API_TOKEN_ALLOWED_SCOPES,
  API_TOKEN_DEFAULT_SCOPES and API_TOKEN_SCOPES_BY_GROUP values that list
  "status" need "burn" added to keep burning; the defaults include it.
* **mcp:** after initialize, MCP clients must send the
  MCP-Protocol-Version header; protocol versions before 2025-06-18 are no
  longer served. Tokens from MCP_OAUTH work only at /mcp, not on /api/v1,
  and expire after 1 day by default (MCP_OAUTH_TOKEN_EXPIRY). Clients sign
  in again when theirs expires.
* **receipts:** RECEIPT_SHOW_VIEWER defaults to name and email (was false);
  set RECEIPT_SHOW_VIEWER=false to keep names off. With STATUS_ACCESS=link
  the status page no longer shows names at all.
* **deps:** require Node.js 24 or newer
* **config:** token lifetimes (API_TOKEN_EXPIRY_OPTIONS,
  API_TOKEN_DEFAULT_EXPIRY, API_TOKEN_MAX_EXPIRY, MCP_OAUTH_TOKEN_EXPIRY,
  API_ADMIN_TOKEN_MAX_EXPIRY) write months as mo now: a value like 6m stops
  the start with "m means minutes; write 6mo". Replace 6m with 6mo. The
  lifetime choices the API lists read 6mo; API clients that still send 6m
  for months keep working.
* **tokens:** with CONFIRM_CHECKBOX=true the MCP tool create_secret
  asks the person by elicitation every time and has no "confirmed"
  argument any more; clients without elicitation get
  confirmation_unavailable.
